---
name: Hackathon judging priorities
description: Product intent and standing constraints for the employer extension.
---

HR, employers and Heads of Department are a primary target audience alongside individual workers. Preserve the individual experience when extending employer workflows.

**Why:** The user explicitly requested both audiences for the Domain 1 Aiversecity Future-Ready Workforce hackathon.

**How to apply:** Judge-facing workflows should be immediately explorable: synthetic autofill for surveys, useful seeded department analysis on first load, and a short route from a shared survey link to employee value and HR planning. Do not substitute presentation-only demonstrations for the working submission-to-dashboard flow.

The employer entry should introduce the complete workflow on an interactive, animated landing page before opening a smooth, simple, slide-by-slide functional demo. Every feature should explain what it is used for, using short, clear instructions rather than dense text.

**Why:** The user repeatedly asked to deeply reference both the individual landing page and its demo for the same quality, interactivity and functionality, rather than opening HR into a dense dashboard.

**How to apply:** Keep the introduction separate from the hands-on workflow, preserve real operations in each chapter, and retain department/campaign context between steps.

For HR demo styling, closely match each individual demo page's fonts, sizes, card spacing and visual hierarchy. Split multiple features into focused sections, with icons and concise guidance.

**Why:** The user emphatically repeated that the individual demo is the styling reference; a separate small-text dashboard interpretation does not meet their expectation.

**How to apply:** Inspect the actual individual workspace components and computed typography before restyling HR. Preserve readability and spacing across every step, not just the first screen.

Preserve the approved individual-style HR demo appearance; improve practical skills-to-reskilling features without moving away from the core direction.

**Why:** The user confirmed the demo UI looks much better and explicitly asked that feature upgrades stay close to the core direction.

**How to apply:** Prefer clearer skill evidence, relevant learning actions and useful human-review outputs over unrelated HR administration features.
