# NexusTalent connected demo walkthrough

Start at `/#home` with **Plans evolve. Progress stays.** The pitch preview is labelled illustrative; the full career workspace uses the backend. A returning user can resume the device-local workspace.

1. Start with a fictional sample or import/paste synthetic experience. Original files are read in the browser; extracted text and the reviewed form are processed in memory by `/api/intake`.
2. Review skills, tasks, goals, interest and weekly learning time. Create the workspace and point out the connected-service/evidence receipt.
3. Open **Future roles**, inspect the server's score components, known skills and full gap. Compare alternatives. Role profiles are authored directions, not verified vacancies.
4. Open **Skills radar** and refresh public research through the backend. Inspect publication date, retrieval time, DOI and the rule mapping metadata to a small model effect. Cached/stale/unavailable evidence is labelled; no invented fallback is presented as live.
5. Choose **Faster AI adoption** or **Green transition**. Review the proposed scores and next-skill changes. Accept the proposal or restore the earlier scenario and evidence revision.
6. Open **Learning plan**. Every role gap and prerequisite has an ordered step, estimate, practice output, public resource where appropriate and SDG links. Complete a step and show it remains after another scenario change. The weekly schedule reflects unfinished work.
7. Save the plan and download the brief. Source provenance, server score explanations, assumptions and the decision history are included. Plans, notes and completion stay on this device.

The API uses explainable CPU rules. Research metadata does not measure Malaysian vacancies or validate a prediction. Personal signals are bounded simulations, isolated from retrieved research and from other users. A server failure produces a visible recovery action rather than a local ranking disguised as a backend result.
